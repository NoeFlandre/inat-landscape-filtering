# Grid'5000

This page tells how to run the `embed` step on Grid'5000 GPUs, in agreement with the
[usage policy](https://www.grid5000.fr/w/Grid5000:UsagePolicy) and the
[storage quotas](https://www.grid5000.fr/w/Storage).

## Work split

| Step | Where | Why |
|---|---|---|
| `measure`, `ingest`, `sample` | outside Grid'5000 | They read the 37 GB metadata dump. Grid'5000 does not need it. |
| `state push` | outside Grid'5000 | Puts the sample in the private state repository on Hugging Face. |
| `embed` | Grid'5000, parallel 1-hour GPU jobs on all sites | It needs a GPU. |
| `score`, `publish` | Grid'5000, one 1-hour CPU job (`scripts/g5k/publish.oar`), or outside Grid'5000 | They need no GPU. |

## Policy

- **Short jobs.** Each job has a walltime of 1 hour. A job of 1 hour or less, submitted less than 10 minutes before it starts, does not count in the daytime quota. Thus the jobs can run at any time.
- **Frontends.** Use the frontend only to clone the repository and submit jobs. The job installs the Python environment on the node.
- **Network.** The jobs download the 240 px photos from the iNaturalist Open Data bucket (about 25 KB each) and upload the embeddings to Hugging Face. For 1.8 million photos, this is about 45 GB in and 3 GB out. Tell the Grid'5000 staff before a larger run.
- **Acknowledgement.** Acknowledge Grid'5000 in each publication that uses these results, and add the publication to HAL with "GRID5000" in the collaboration field.

## Storage

| Place | Content | Size |
|---|---|---|
| `/home` (25 GB quota, per site) | repository, `~/.hf_token`, `~/.inat-landscape/` (oarsub options, failure file and job logs of each slot) | less than 50 MB |
| node `/tmp` (deleted after the job) | Python environment, uv cache, Hugging Face cache, work directory, in one folder for each slot | up to about 10 GB |
| Hugging Face | embeddings (public dataset), state (private repository) | about 3 GB |

The Python environment is on the node `/tmp`, because most `/home` directories have no free 6 GB. Thus each job installs it again (about 3 GB of downloads).

## Procedure

1. On each site, set up the site once. Open a terminal on its frontend and run this command. It clones the repository and asks once for a Hugging Face write token (the token is not shown and is saved with mode 600 in `~/.hf_token`):

    ```bash
    curl -fsSL https://raw.githubusercontent.com/NoeFlandre/inat-landscape-filtering/claude/new-session-8l7p9c/scripts/g5k/bootstrap.sh | bash
    ```

2. On a machine that reaches each frontend with `ssh SITE`, run `./scripts/g5k/submit_all.sh`. It:
    - stops if a job chain of an earlier run is still queued or running,
    - finds the free GPUs of each site (`scripts/g5k/free_gpus.py` reads `oarnodes`),
    - gives each free GPU one worker slot `I/N`, with N the count of all free GPUs,
    - submits one 1-hour job for each slot, on the site and cluster of its GPU, with the queue (`production`) and job type (`exotic`) of that cluster.
3. While photos are left, each job queues the next job of its slot, with the same options. The nodes have no OAR commands, so the job submits through the frontend of its site (`ssh frontend.SITE.grid5000.fr`). Each job runs a copy of `embed.oar` on the node `/tmp`: a `git pull` on the NFS `/home` replaces the file, and Bash stops a script that it reads from a replaced file ("Stale file handle"). The chain stops when no photo is left, or when a job made no progress (for example if all downloads fail). The progress shows on Hugging Face: one shard for each 50,000 photos, and one shard at the end of each job.
4. Look at the jobs with `oarstat -u` on each site. Read the output in `~/.inat-landscape/logs/<job id>.out` and `.err`.
5. During the run, refresh the card and the figures on Hugging Face from a CPU node. The job runs `score` and `publish --no-images` every 20 minutes:

    ```bash
    oarsub -l "host=1,walltime=1:00:00" -p "gpu_count=0" "$HOME/inat-landscape-filtering/scripts/g5k/publish.oar refresh"
    ```

6. When `embed --plan` gives `todo=0` for all slots, do one retry pass for the failed downloads: one job of the slot `0/1`. Then publish with the images (`publish.oar final`, same command).
7. Delete `~/.hf_token` on each site.

A queued successor waits for its predecessor, so it does not start within 10 minutes of its submission. Thus it counts in the daytime quota: at most 1 GPU-hour for each slot and hour.

The cu126 PyTorch build does not use AMD GPUs, ARM boards, Pascal or older GPUs, and Blackwell GPUs. `free_gpus.py` leaves them out.
