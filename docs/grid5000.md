# Grid'5000

This page tells how to run the `embed` step on Grid'5000 GPUs, in agreement with the
[usage policy](https://www.grid5000.fr/w/Grid5000:UsagePolicy) and the
[storage quotas](https://www.grid5000.fr/w/Storage).

## Work split

| Step | Where | Why |
|---|---|---|
| `measure`, `ingest`, `sample` | outside Grid'5000 | They read the 37 GB metadata dump. Grid'5000 does not need it. |
| `state push` | outside Grid'5000 | Puts the sample in the private state repository on Hugging Face. |
| `embed` | Grid'5000, parallel 1-hour GPU jobs | It needs a GPU. |
| `score`, `publish` | outside Grid'5000 | They need no GPU. |

## Policy

- **Short jobs.** Each job has a walltime of 1 hour. A job of 1 hour or less, submitted less than 10 minutes before it starts, does not count in the daytime quota. Thus the jobs can run at any time.
- **Frontends.** Use the frontend only to clone the repository and submit jobs. The job installs the Python environment on the node.
- **Network.** The jobs download the 240 px photos from the iNaturalist Open Data bucket (about 25 KB each) and upload the embeddings to Hugging Face. For 1.8 million photos, this is about 45 GB in and 3 GB out. Tell the Grid'5000 staff before a larger run.
- **Acknowledgement.** Acknowledge Grid'5000 in each publication that uses these results, and add the publication to HAL with "GRID5000" in the collaboration field.

## Storage

| Place | Content | Size |
|---|---|---|
| `/home` (25 GB quota, per site) | repository, Python environment, `uv` | about 7 GB |
| node `/tmp` (deleted after the job) | uv cache, Hugging Face cache, work directory | up to about 10 GB |
| Hugging Face | embeddings (public dataset), state (private repository) | about 3 GB |

## Procedure

1. Open a terminal on a frontend of a site with GPUs (for example Lille or Lyon), with SSH or with the browser terminal of [JupyterHub](https://intranet.grid5000.fr/notebooks).
2. Run this command. It clones the repository, asks once for a Hugging Face write token (the token is not shown and is saved with mode 600 in `~/.hf_token`), and submits 4 parallel jobs:

    ```bash
    curl -fsSL https://raw.githubusercontent.com/NoeFlandre/inat-landscape-filtering/claude/new-session-8l7p9c/scripts/g5k/bootstrap.sh | bash -s -- 4
    ```

3. While photos are left, each job queues the next job of its worker. The chain stops when no photo is left. The progress shows on Hugging Face: one shard for each 50,000 photos.
4. Look at the jobs with `oarstat -u`. Read the output in `inat-embed.<job id>.out` and `.err`.
5. When the work is done, delete `~/.hf_token`.

A queued successor waits for its predecessor, so it does not start within 10 minutes of its submission. Thus it counts in the daytime quota: at most 1 GPU-hour for each worker and hour, which is far below the quota.
